# Analyzer and code fix patterns

## 1. Analyzer skeleton

The file layout matches every other analyzer: regions, full XML documentation, one descriptor, and a `.NET Framework` gate when applicable.

```vb
#Region " Option Statements "

Option Strict On
Option Explicit On
Option Infer Off

#End Region

#Region " Imports "

Imports System.Collections.Generic
Imports System.Collections.Immutable

Imports Microsoft.CodeAnalysis
Imports Microsoft.CodeAnalysis.Diagnostics
Imports Microsoft.CodeAnalysis.Operations

#End Region

#Region " ManagedThreadIdAnalyzer "

Namespace DevCase.Core.Diagnostics.Dotnet.CodeAnalysis.Analyzers

    ''' <summary>
    ''' Reports <c>Thread.CurrentThread.ManagedThreadId</c> (rule <see cref="DiagnosticIds.CurrentThreadManagedThreadId"/>).
    ''' </summary>
    '''
    ''' <remarks>
    ''' The rule runs only in .NET Framework projects: on modern .NET, the built-in rule CA1840 reports the same code.
    ''' </remarks>
    <DiagnosticAnalyzer(LanguageNames.VisualBasic)>
    Public NotInheritable Class ManagedThreadIdAnalyzer : Inherits DiagnosticAnalyzer

#Region " Properties "

        ''' <summary>
        ''' Gets the descriptor of the rule reported by this analyzer.
        ''' </summary>
        Public Overrides ReadOnly Property SupportedDiagnostics As ImmutableArray(Of DiagnosticDescriptor)
            Get
                Return ImmutableArray.Create(DevCaseDescriptors.CurrentThreadManagedThreadId)
            End Get
        End Property

#End Region

#Region " Constructors "

        ''' <summary>
        ''' Initializes a new instance of the <see cref="ManagedThreadIdAnalyzer"/> class.
        ''' </summary>
        Public Sub New()
        End Sub

#End Region

#Region " Public Methods "

        ''' <summary>
        ''' Registers the analysis actions.
        ''' </summary>
        '''
        ''' <param name="context">
        ''' The analysis context.
        ''' </param>
        '''
        ''' <exception cref="ArgumentNullException">
        ''' Thrown when <paramref name="context"/> is <see langword="Nothing"/>.
        ''' </exception>
        Public Overrides Sub Initialize(context As AnalysisContext)

            If context Is Nothing Then
                Throw New ArgumentNullException(NameOf(context))
            End If

            context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None)
            context.EnableConcurrentExecution()
            context.RegisterCompilationStartAction(AddressOf ManagedThreadIdAnalyzer.OnCompilationStart)
        End Sub

#End Region

#Region " Private Methods "

        ''' <summary>
        ''' Registers the operation action when the compilation targets .NET Framework.
        ''' </summary>
        '''
        ''' <param name="context">
        ''' The compilation start context.
        ''' </param>
        Private Shared Sub OnCompilationStart(context As CompilationStartAnalysisContext)

            If Not UtilAnalyzerSemantic.IsNetFramework(context.Compilation) Then
                Exit Sub ' Modern .NET: the built-in rule CA1840 reports the same code.
            End If

            context.RegisterOperationAction(UtilAnalyzerFiles.SkipExcludedOperations(AddressOf ManagedThreadIdAnalyzer.AnalyzePropertyReference),
                                            OperationKind.PropertyReference)
        End Sub

        ' ... AnalyzePropertyReference: detect, build the FixReplacement actions, report.

#End Region

    End Class

End Namespace

#End Region
```

### Mandatory registration rules

- Always call `ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None)` and `EnableConcurrentExecution()`.
- Wrap every action with `UtilAnalyzerFiles.SkipExcludedNodes`, `SkipExcludedOperations`, `SkipExcludedSymbols` or `SkipExcludedTrees`. This excludes `.Designer`, `AssemblyInfo`, `GlobalSuppressions`, `.g`, `.generated` and `<auto-generated>` files consistently.
- Resolve framework types once, in `OnCompilationStart` (`GetTypeByMetadataName`). If a type or member the fix needs does not exist, do not register.
- Choose the lightest entry point that sees every form:
  - `RegisterOperationAction` when semantics matter: it sees through syntax forms, named arguments and implicit conversions.
  - `RegisterSyntaxNodeAction` when the shape matters, such as statements, trivia or `If` blocks. Register **every** kind that can carry the pattern. For example, DCA081 starts from `InvocationExpression`, not from `MultiLineIfBlock`, so that ternaries, `AndAlso` and guard clauses are found.
- Analyzers are stateless (`Shared` methods). Per-compilation state lives in closures created in `OnCompilationStart`.

### Detection rules

- **Bind, don't match text.** Use `SemanticModel` and `UtilAnalyzerSemantic.IsMember(symbol, "Full.Type.Name", "Member")` and `HasMetadataName`. A look-alike name (`myAsyncSettings.Result`) must never be reported.
- Normalize expressions before testing kinds:
  - `UtilAnalyzerSyntax.SkipParentheses(expr)` going down;
  - `UtilAnalyzerSyntax.WalkUpParentheses(expr)` going up, to find the real parent;
  - in operations, skip `IConversionOperation` and `IParenthesizedOperation`.
- Compare code with `UtilAnalyzerSyntax.AreEquivalentExpressions` (ignores trivia and parentheses).
- Only reuse an expression twice, or drop it, when `UtilAnalyzerSyntax.IsSimpleReference` / `Not MayHaveSideEffects` allows it.
- Bail out (no report) when `UtilAnalyzerSyntax.HasInnerDirectives(node)`, because another configuration may compile other statements.
- Reads inside a lambda may run later; treat them as unsafe unless the whole pattern is inside the lambda.
- Check the `.NET Framework` reference assemblies, not modern .NET, for API existence: `IReadOnlyList(Of T)` does not imply `IList(Of T)`, and `Environment.CurrentManagedThreadId` exists in 4.5+.

## 2. Fix protocol: `FixReplacement` + `ReplacementCodeFixProvider`

Most fixes are computed **by the analyzer** and stored in the diagnostic properties. The generic `ReplacementCodeFixProvider` applies them, so there is one provider for many rules and Fix All is the same for all of them.

```vb
' One FixReplacement per lightbulb action; one text per edited span (AdditionalLocations).
Dim actions As New List(Of FixReplacement)()
If typeName IsNot Nothing AndAlso
   UtilAnalyzerSemantic.IsMember(UtilSpeculativeBinding.GetSymbol(model, position, replacement), "System.Environment", "CurrentManagedThreadId") Then
    actions.Add(New FixReplacement("Use Environment.CurrentManagedThreadId", "CurrentManagedThreadId", replacement))
End If
' editedSpans empty = the action replaces the diagnostic location itself.
context.ReportDiagnostic(UtilFixProperties.CreateDiagnostic(DevCaseDescriptors.CurrentThreadManagedThreadId, reference.Syntax.GetLocation(),
                                                            Enumerable.Empty(Of Location)(), actions))
```

- `New FixReplacement(title, key, ParamArray texts)`:
  - `title` is the lightbulb text: imperative, with no trailing period.
  - `key` is the short action key; the equivalence key becomes `DCAnnn.key` (tests pass `equivalenceKey:="DCA081.TryGetValue"`).
  - `texts` holds one replacement per edited span, in the same order as `editedSpans`.
- `UtilFixProperties.CreateDiagnostic(descriptor, location, editedSpans, actions, ParamArray messageArguments)`:
  - The edited spans must not overlap.
  - A zero-length span is an insertion.
  - An empty `actions` reports without a fix (still a valid diagnostic).
- The diagnostic properties are `Fix.Count`, `Fix.n.Title`, `Fix.n.Key` and `Fix.n.m`. Never write them by hand.
- Fix All, in `ReplacementCodeFixProvider`, merges all diagnostics of a document. Insertions at the **same position** are concatenated (several fields before the same member), so make inserted texts self-contained, each with its own line break and indentation.
- Order the actions with the behavior-preserving one first (see SKILL.md §1.3). Examples:
  - DCA060 offers `Visible`, `Content`, `DefaultValue`, `Hidden`;
  - DCA026 puts first the encoding that the API already uses: `New UTF8Encoding(encoderShouldEmitUTF8Identifier:=False)` for `System.IO` APIs, `Encoding.UTF8` for `My.Computer.FileSystem`; `Encoding.Default` always comes last;
  - DCA009 offers `Ordinal` and `OrdinalIgnoreCase`.

### Building replacement text

- Get type names as the file can write them with `UtilSpeculativeBinding.GetTypeName(model, position, typeSymbol)`, which respects the file's imports. Never hardcode `System.` prefixes that the file does not need, or omit ones it does.
- Validate every replacement with `UtilSpeculativeBinding.GetSymbol` / `GetExpressionType` at the code's position. **Speculative binding does not check generic constraints** (see DCA059); check them yourself.
- Insert new statements with the anchor's indentation (`UtilAnalyzerSyntax.GetLineIndentation(token)`) and the tree's line ending (`UtilAnalyzerSyntax.GetEndOfLine(tree)`). Never use `vbCrLf` or `Environment.NewLine`.
- New local names must not collide. DCA081 uses `value`, then `value1`, `value2`, … taking into account the other diagnostics of the same scope, so Fix All stays unique. DCA084 numbers fields per type across `Partial` files.
- Keep comments: use `UtilAnalyzerSyntax.TryGetLineComments(node, lines, comments, commentLines)`.
  - End-of-line comments of the removed lines go **after** the new line.
  - Full-line comments go **before** it.
  - If any other comment would be lost (e.g. after a `_` continuation), offer no action.
- Insert declarations only where a statement list exists (`UtilAnalyzerSyntax.GetBlockStatements(parent)` contains the anchor). The bodies of single-line `If` and single-line lambdas cannot host them: offer no action there.
- Option-sensitive fixes must also compile with `Option Strict Off` and `Option Infer On`. Type literals explicitly (`5L`, `0S`, `CByte(7)`, `0.5R`, `1.5F`, `"x"c`) so that overloads bind as intended.

## 3. Dedicated `CodeFixProvider` (only when needed)

Use one when the fix needs the workspace: other documents (partial types, DCA006), the formatter, or document-wide restructuring.

- Apply `<ExportCodeFixProvider(LanguageNames.VisualBasic, Name:=NameOf(XCodeFixProvider)), [Shared]>`, and set `Public NotInheritable Class XCodeFixProvider : Inherits CodeFixProvider`.
- Return `WellKnownFixAllProviders.BatchFixer` (or a custom one) from `GetFixAllProvider`. Every provider must support Fix All.
- Each ID is fixed by exactly one provider (a test enforces it).
- Find the node from the diagnostic span. If it is not what you expect, throw `InvalidOperationException` (fail fast); do not return silently.
- Apply text changes with `UtilCodeFix.ApplyTextChangesAsync` to keep trivia intact. When using syntax APIs, never use `SyntaxRemoveOptions.KeepNoTrivia` on nodes that may carry directives.

## 4. Documentation-generating fixes (DCA005, DCA007, DCA008, DCA012)

- Write empty sections on **one line**: `''' <exception cref="ArgumentException"></exception>`. Never write a block of blank lines:

  ```vb
  ' ❌ Bad
  ''' <exception cref="ArgumentException">
  '''
  ''' </exception>

  ' ✔️ Good
  ''' <exception cref="ArgumentException"></exception>
  ```

- Group consecutive `<exception>` tags with **no** blank `'''` between them. Put one `'''` separator before the group, and no dangling `'''` before the declaration. Blank `'''` lines have no trailing space.

  ```vb
  ' ❌ Bad
  ''' <summary>
  ''' Displays the welcome banner.
  ''' </summary>
  '''
  ''' <exception cref="ArgumentNullException"></exception>
  '''
  ''' <exception cref="ArgumentException"></exception>
  '''
  Private Sub DisplayWelcomeBanner(arg1 As String)

  ' ✔️ Good
  ''' <summary>
  ''' Displays the welcome banner.
  ''' </summary>
  '''
  ''' <exception cref="ArgumentNullException"></exception>
  ''' <exception cref="ArgumentException"></exception>
  Private Sub DisplayWelcomeBanner(arg1 As String)
  ```

- Public and Friend constructors get the standard summary: "Initializes a new instance of the `<see cref="T"/>` class." (or "structure", or `cref="T(Of U)"`).
- Default `<param>` texts are derived from the name and type ("The file path.", `<see langword="True"/>` to overwrite; otherwise, `<see langword="False"/>`.). They are needed so that the fixed code no longer triggers DCA008; a "fix" that leaves the warning is not a fix.
- Never invent conditions ("Thrown when … is Nothing") for `<exception>`: leave them empty.

## 5. Settings (`DevCaseAnalyzerOptions`)

- Options are `.editorconfig` keys with the prefix `devcase_analyzers.`, such as `dca017_timeout_ms` (default 30000), `dca011_condition`, `default_namespace`, `configure_await_named_argument` and `dca010_enabled`.
- An invalid value falls back to the automatic behavior; it never throws inside an analyzer.
- Document every option in the README *Configuration* section and in the rule document (`## ⚙️ Configuration`).
